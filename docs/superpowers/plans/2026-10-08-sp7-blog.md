# SP7 Blog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the notes section, hidden behind `BLOG_ENABLED` until there are three notes:

- P08 index with category chips
- P09 note page
- Home "Latest note" block and the `06 NOTES` nav item
- RSS per language and build-time OG images

**Architecture:**

- **Flag.** `BLOG_ENABLED` is an `astro:env` build-time boolean (default `false`). It is exposed only through `src/config/blog.ts`, because `site.ts` is also imported by Node tests, where `astro:env` doesn't resolve.
- **Routes.** Every blog route uses `getStaticPaths` and returns `[]` when the flag is off. The index pages use a single-param trick (`[notes].astro`), and the feeds use `[file].xml.ts` so they don't collide with `[slug].astro`.
- **Logic.** Pure functions in `src/lib/notes.ts` (listing, twins, prev/next, RSS) and `src/lib/og.ts` (Satori → resvg).
- **Testing.** Playwright builds with the flag on. CI's default build is checked by `scripts/check-blog-hidden.mjs`.

**Tech Stack:** Astro 7 + MDX content collections, vanilla TS, plain CSS tokens, Satori + @resvg/resvg-js (new devDependencies), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-08-sp7-blog-design.md`

## Global Constraints

- **Dependencies:** npm only. The only new ones are `satori` and `@resvg/resvg-js` as devDependencies (justify them in the PR). No React: the Satori element tree is plain objects.
- **Copy:** verbatim from `docs/handoff/design/Blog Index.dc.html` and `Blog Post.dc.html` COPY (EN and ES). Never invent visible strings. The `N MIN` format and `RSS ↗` come from the markup.
- **Markup values:** sizes, borders and gaps come from the same files. Components use semantic tokens only. The OG image uses literal light-theme hex values (`#F2F3EF`, `#15181C`, `#5B626A`, `#2B55C8`).
- **Design rules:** radius 0, glyphs only, 44px targets on coarse pointers, `aria-pressed` on chips.
- **Never edited:** `src/styles/tokens/*` and `src/styles/motion.css`.
- **Flag off:** no blog page, feed, OG image, nav item, Home block or link is generated.
- **Workflow:** run tests locally with `npx playwright test --workers=1`. Commits follow `.gitmessage` with scope `blog` (`ci`, `deps`, `docs` where they fit). Working dir: `.worktrees/sp7-blog`.

## Review Focus

1. **A note published in only one language.** It is listed in the other language with the `ONLY IN …` label, linking to its real URL. The note's language switch goes to the other language's notes index. Unit tests in Task 2.
2. **Draft notes never leak.** No index row, feed item, OG image or route for N-01. Unit test in Task 2 and e2e 404 in Task 5.
3. **Titles or deks with `&`, `<` or `"` in the feed.** They are XML-escaped, so the feed still parses. Unit test in Task 2.
4. **The flag-off build linking the blog anywhere** (nav, Home, footer, a stray `href`). The check script fails. A fixture test in Task 3 and the CI step.
5. **Chip filter state.** With JS off nothing is pressed and every row shows. With JS, picking an empty category shows the empty state, and `SHOW ALL NOTES` restores everything. e2e in Task 4.

```ts
import { ROUTES, other, type Lang } from '../i18n/routes';
import { ui } from '../i18n/ui';

export const CATEGORIES = ['process', 'automation', 'engineering', 'cases'] as const;
export type Category = (typeof CATEGORIES)[number];
export interface NoteData {
  id: string;
  lang: Lang;
  slug: string;
  title: string;
  dek: string;
  date: string;
  category: Category;
  minutes: number;
  tags: string[];
  draft: boolean;
}
export interface NoteLike {
  data: NoteData;
}
export type Listed<T> = T & { fallback: boolean };

const published = <T extends NoteLike>(all: T[]) => all.filter((n) => !n.data.draft);
const newestFirst = (a: NoteLike, b: NoteLike) =>
  b.data.date.localeCompare(a.data.date) || b.data.id.localeCompare(a.data.id);

export const noteUrl = (lang: Lang, slug: string) => `${ROUTES.notes[lang]}/${slug}`;
export const noteHref = (n: NoteLike) => noteUrl(n.data.lang, n.data.slug);

/** Published notes for a language, newest first; notes that exist only in the other language
 *  are included with fallback: true (index label "ONLY IN …"). */
export function listNotes<T extends NoteLike>(all: T[], lang: Lang): Listed<T>[] {
  const pub = published(all);
  const own = pub.filter((n) => n.data.lang === lang);
  const ids = new Set(own.map((n) => n.data.id));
  const foreign = pub.filter((n) => n.data.lang !== lang && !ids.has(n.data.id));
  return [
    ...own.map((n) => ({ ...n, fallback: false })),
    ...foreign.map((n) => ({ ...n, fallback: true })),
  ].sort(newestFirst);
}

/** Static paths for one language. Duplicate ids or slugs would silently overwrite a page. */
export function notePaths<T extends NoteLike>(all: T[], lang: Lang) {
  const own = published(all)
    .filter((n) => n.data.lang === lang)
    .sort(newestFirst);
  const seen = { id: new Set<string>(), slug: new Set<string>() };
  for (const n of own) {
    if (seen.id.has(n.data.id)) throw new Error(`notes: duplicate id ${n.data.id} in ${lang}`);
    if (seen.slug.has(n.data.slug))
      throw new Error(`notes: duplicate slug ${n.data.slug} in ${lang}`);
    seen.id.add(n.data.id);
    seen.slug.add(n.data.slug);
  }
  return own.map((entry) => ({ params: { slug: entry.data.slug }, props: { entry } }));
}

export const twinOf = <T extends NoteLike>(all: T[], n: T) =>
  published(all).find((t) => t.data.id === n.data.id && t.data.lang !== n.data.lang);

/** Language switch target: the twin, or the other language's notes index (no hreflang). */
export function noteAlternate<T extends NoteLike>(all: T[], n: T) {
  const twin = twinOf(all, n);
  return twin
    ? { alternate: noteHref(twin), hreflang: true }
    : { alternate: ROUTES.notes[other(n.data.lang)], hreflang: false };
}

/** list is newest first: prev = the older neighbour, next = the newer one. */
export function prevNext<T extends NoteLike>(list: T[], id: string): { prev?: T; next?: T } {
  const i = list.findIndex((n) => n.data.id === id);
  return { prev: list[i + 1], next: i > 0 ? list[i - 1] : undefined };
}

export const dateLabel = (date: string) => date.slice(0, 7).replace('-', '.');
export const categoryLabel = (c: Category, lang: Lang) =>
  ui[lang].notes.cats[CATEGORIES.indexOf(c) + 1];

export function categoryCounts(list: NoteLike[]) {
  const counts = { all: list.length, process: 0, automation: 0, engineering: 0, cases: 0 };
  for (const n of list) counts[n.data.category]++;
  return counts;
}

const ESC: Record<string, string> = {
  '&': '&amp;',
  '<': '&lt;',
  '>': '&gt;',
  '"': '&quot;',
  "'": '&apos;',
};
const xml = (s: string) => s.replace(/[&<>"']/g, (c) => ESC[c]);
/** Noon UTC, so the weekday never shifts across time zones. */
export const rfc822 = (date: string) => new Date(`${date}T12:00:00Z`).toUTCString();

export function rssFeed(o: {
  lang: Lang;
  title: string;
  description: string;
  base: string;
  items: NoteData[];
}): string {
  const abs = (p: string) => new URL(p, o.base).href;
  const items = o.items
    .map((n) => {
      const url = abs(noteUrl(n.lang, n.slug));
      return `<item><title>${xml(n.title)}</title><link>${url}</link><guid isPermaLink="true">${url}</guid><pubDate>${rfc822(n.date)}</pubDate><description>${xml(n.dek)}</description></item>`;
    })
    .join('');
  const index = abs(ROUTES.notes[o.lang]);
  return `<?xml version="1.0" encoding="UTF-8"?><rss version="2.0" xmlns:atom="http://www.w3.org/2005/Atom"><channel><title>${xml(o.title)}</title><link>${index}</link><atom:link href="${index}/rss.xml" rel="self" type="application/rss+xml"/><description>${xml(o.description)}</description><language>${o.lang}</language>${items}</channel></rss>`;
}
```

Before I write a line of code, I write one page. The client reads it, we fix what is wrong, and they sign it. Only then do I send a fixed price.

## One page, not a document

Long specs get skimmed. A single page forces both of us to decide what matters. If something does not fit, it is probably not part of the first version.

> The spec is the contract with whoever maintains the code — usually me.

## What goes on it

Every spec has the same five blocks, in the same order, so clients learn to read them fast.

```text
SPEC FM-NN
01 PROBLEM   one sentence
02 USERS     roles, and what each can do
03 MODULES   max 6, each with one verb
04 DATA      the tables that matter
05 METRIC    the one number that says it worked
```

### What I leave out

- Screens and pixels. Those come in week one, on a live link.
- Nice-to-haves. They go in a "later" list at the bottom.
- Technology choices the client does not need to approve.

## What it saves

On ChurchApp the spec took one afternoon. It named seven modules and one metric. The first public release shipped ten days later, with no module added or dropped. The full story is in the [case study](/en/work/churchapp).

// CI: the default build (BLOG_ENABLED unset) must neither contain nor link the notes section.
import { readdir, readFile } from 'node:fs/promises';
import { join, relative, sep } from 'node:path';

const root = process.argv[2] ?? '.vercel/output/static';
const BLOG = /^\/(en\/notes|es\/notas|og\/notes)(\/|$)/;
const LINK = /href="\/(en\/notes|es\/notas)(["/?#])/;
const found = [];

async function walk(dir) {
  for (const e of await readdir(dir, { withFileTypes: true })) {
    const full = join(dir, e.name);
    const rel = '/' + relative(root, full).split(sep).join('/');
    if (BLOG.test(rel)) {
      found.push(rel);
      continue;
    }
    if (e.isDirectory()) await walk(full);
    else if (e.name.endsWith('.html') && LINK.test(await readFile(full, 'utf8')))
      found.push(`${rel} links to the blog`);
  }
}

await walk(root);
if (found.length) {
  console.error(
    `The blog is off (BLOG_ENABLED=false) but the build contains:\n${found.join('\n')}`,

  process.exit(1);
}
