# SP8b Go live Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the last placeholders (portrait, ChurchApp screenshots, prices) and ship the site to production as v1.0.0 on `https://fmyers-dev.vercel.app`.

**Architecture:** Content and asset changes only. `Portrait.astro` and `Figure.astro` already swap the hatch for an optimised image when a file exists under `src/assets/`, so no component changes. The release uses the SP8a machinery: a `Release-As: v1.0.0` line in the PR body (the squash body) makes `tag.yml` tag `v1.0.0`, then `release/v1.0.0` goes to `main` with a merge commit.

**Tech Stack:** Astro 7 (static + `astro:assets`), Playwright, Python/Pillow (local cropping only; not a project dependency).

**Spec:** `docs/superpowers/specs/2026-10-13-sp8b-go-live-design.md`

## Global Constraints

- No new dependencies. Pillow runs from the agent's machine to crop assets; the repo gets only the resulting files.
- Figure ratios (handoff C12): screenshots 16:10, portrait 4:5.
- Prices: MVP `3200`, Automation `600`, Fractional `2000` (month), maintenance "From $100/month" / "Desde $100/mes", FAQ and `ui.ts` "from $100 a month" / "desde $100 al mes".
- `docs/handoff/` is never edited.
- The PR body contains exactly one line `Release-As: v1.0.0`, on its own line; nothing else in the body may mention that keyword (`next-tag` fails on near misses).
- Never commit, push, merge or release without the owner's go-ahead (global approval for this SP covers commits and pushes on the feature branch; merges and the release PR are asked separately).

## Review Focus

1. Screenshot privacy: the committed ChurchApp images show no personal data (names, emails, phones). Expected: only counts, module titles and public copy.
2. Price drift: any other place showing a price (Home compact cards, Services FROM cells, Pricing cards, FAQ, OG text, JSON-LD) still shows an old figure. Expected: every rendered price comes from the pricing collection or the updated strings.
3. Image weight and LCP: the portrait (About LCP) and the ChurchApp card (Work LCP) stay inside Lighthouse ≥ 95 on mobile.
4. Dark theme: the screenshots' white backgrounds inside the 1px ink frame in dark mode. Expected: readable, framed, no layout shift.
5. The release: `release/v1.0.0` points exactly at the `v1.0.0` tag commit; `release-source` passes; production deploy serves the new build.
