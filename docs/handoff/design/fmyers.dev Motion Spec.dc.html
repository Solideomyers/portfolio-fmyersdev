Motion and micro-interactions

How fmyers.dev moves. The personality is measured, like a plotter drawing a sheet: lines are traced and sheets slide into place, but feedback is never slow. Live demos are in Sheet D of the design system.

1. Principles

  1. Measured, like a plotter. Entries take 350ms, sheets 450ms and strokes 600ms. Nothing runs longer than 600ms.
  2. Feedback is always fast. Press 160ms, hover 200ms, language 150ms. The personality never slows input.
  3. Lines get drawn. Frames, checks and strike-throughs are stroked in. Nothing appears from scale(0); the minimum is 0.6 with opacity.
  4. Motion never blocks. Content is clickable during every animation, and nothing is hidden when JavaScript is off.
  5. Reduced motion means opacity only. No translate and no scale, but fades remain.
  6. Only transform, opacity, clip-path and stroke-dashoffset. Never animate layout properties.

4. Never animate

  • Keyboard focus rings and keyboard-initiated actions
  • Nav jumps between sheets. Use smooth scroll only, with no element motion.
  • Content that has already been revealed, on its second pass
  • The status dot (no pulse), prices, spec values or anything on a loop
  • Elevation on hover (no lift, no shadow)

5. Implementation in Astro

Stack: CSS for press, hover, toast, menu and ruler. Astro View Transitions for page morph, theme and language. Motion (motion, vanilla build) for the signature, inView reveals, the confirmation and the crosshair spring. Load Motion only on pages that use it.

// scripts/reveal.ts
import { inView, animate, stagger } from 'motion';
const reduce = matchMedia('(prefers-reduced-motion: reduce)').matches;
inView('[data-reveal]', (el) => {
  animate(el.querySelectorAll(':scope > *'),
    reduce ? { opacity: [0, 1] } : { opacity: [0, 1], transform: ['translateY(12px)', 'none'] },
    { duration: 0.35, delay: stagger(0.06), ease: [0.23, 1, 0.32, 1] });
}, { amount: 0.2 });

FIG. 1 — Base wiring. Shared CSS lives in design-system/motion.css.

// scripts/theme.ts — circular reveal from the toggle
btn.addEventListener('click', (e) => {
  const next = root.dataset.theme === 'dark' ? 'light' : 'dark';
  if (!document.startViewTransition || reduce) return apply(next);
  const { x, y } = center(e.currentTarget);
  const r = Math.hypot(Math.max(x, innerWidth - x), Math.max(y, innerHeight - y));
  root.classList.add('theme-reveal');
  const vt = document.startViewTransition(() => apply(next));
  vt.ready.then(() => root.animate(
    { clipPath: [`circle(0 at ${x}px ${y}px)`, `circle(${r}px at ${x}px ${y}px)`] },
    { duration: 450, easing: 'cubic-bezier(0.77,0,0.175,1)', pseudoElement: '::view-transition-new(root)' }));
  vt.finished.finally(() => root.classList.remove('theme-reveal'));
});

FIG. 2 — Theme toggle. Persist the choice in localStorage and set data-theme inline in <head> to avoid a flash.

6. QA checklist

  • Play every animation at 4× slower in DevTools and check that properties stay in sync.
  • Toggle prefers-reduced-motion. Only fades should remain, and all content must be visible.
  • Disable JavaScript. Every [data-reveal] must stay visible.
  • On a touch device: no crosshair, no hover states, and menu hit targets of at least 44px.
  • Throttle the CPU 4×. The signature must stay smooth, so it uses transforms only.
  • Check the theme and language swaps in Safari and Firefox. Without View Transitions, the swap is instant.
